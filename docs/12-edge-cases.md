# STEP 12. Edge Case 카탈로그

> 각 항목은 `spec/golden/golden_set.jsonl`에 대응 케이스가 있어야 한다. 없으면 추가할 것.

## A. 이름 매칭이 만드는 지옥

| ID | 상황 | 잘못된 결과 | 대응 |
|---|---|---|---|
| A1 | 일반명사가 사명 (한샘, 대한, 신라, 삼양, 대성, 태광) | "신라 유적 발굴" → 신라젠 | `company_alias.is_ambiguous=true` → KM −25, score cap 80, 그리고 **개체 `subtype`이 회사 도메인과 무관하면 REJECT 유도** |
| A2 | 동음이의 지명 (광주=광역시/경기 광주) | 엉뚱한 지역 기업 | 개체에 `subtype=REGION` + 행정코드 확정 후에만 `LOCATED_IN` 탐색 |
| A3 | 사람 이름 = 사명 (김밥, 정관장…) | | `entity.kind=PERSON`은 `NAME_MATCH` 대신 `PERSON_OF` 엣지가 있을 때만 사업 연관 인정 |
| A4 | 1글자 개체 ("달", "물", "금") | 수십 종목 폭발 | 길이 1은 KM −40, `THEME_DICT` 경로로만 허용 |
| A5 | 영문 약어 충돌 (AI, SK, LG, GS) | | 영문 2자 이하 별칭은 `ALIAS_EXACT`에서 제외 |
| A6 | 구 사명 (하이닉스반도체 → SK하이닉스) | 미매칭 | `alias_type=FORMER` 유지, 배수 0.7 |

## B. 기업 데이터

| ID | 상황 | 대응 |
|---|---|---|
| B1 | 상장폐지/거래정지 | `is_listed=false`면 후보 제외. 거래정지는 후보 포함하되 `MR=null` + "거래정지" 배지 |
| B2 | 신규 상장 (시세 이력 없음) | `volumeRatio20` 계산 불가 → `MR=null` |
| B3 | 스팩(SPAC) | `is_spac=true` 전면 제외 |
| B4 | 우선주 (삼성전자우) | 보통주로 정규화하여 1개 연결로 병합. 우선주는 별도 노출하지 않음 |
| B5 | 지주사·자회사 동시 상장 | 둘 다 노출하되 자회사가 `anchor`, 지주사는 `AFFILIATION`으로 hop+1 |
| B6 | 사명 변경 당일 | 마스터 일 1회 갱신 → 최대 1일 지연. 변경 공시를 트리거로 즉시 갱신 |
| B7 | 같은 이름 계열사 다수 (한국전력 계열) | `AFFILIATION` 확장 시 1홉 제한, 최대 3개 |

## C. 뉴스

| ID | 상황 | 대응 |
|---|---|---|
| C1 | 기사 30개가 같은 사건 | 클러스터링. 미분류 시 피드가 도배됨 |
| C2 | 정정·삭제 기사 | `is_deleted` 표시, 카드 유지 + 링크 비활성 |
| C3 | 광고성/보도자료 | `source_tier=3` + 제목 패턴 필터, `heat_score` 감점 |
| C4 | 낚시 제목 (본문과 무관) | 제목만으로 추출하므로 오염 가능 → `lead` 200자를 함께 넣어 완화 |
| C5 | 주말·연휴 | `trade_date`는 다음 거래일로 귀속. 시세는 직전 종가 + "전일 기준" 배지 |
| C6 | 심야 뉴스 | 다음 거래일 버킷. 알림은 07:00 이후 발송 |
| C7 | 해외 뉴스 (엔비디아 등) | 국내 상장사 아님 → `entity(ORG)`로만 두고 공급망 경로로 국내 종목 도달 |
| C8 | 개체 0개 (지수·시황 기사) | `analysis_status=SKIPPED`, 연결 0건으로 정상 종료 |

## D. 시장 데이터

| ID | 상황 | 대응 |
|---|---|---|
| D1 | 장 시작 전 | `isPreMarket=true`, MR=null, 전일 종가 표시 |
| D2 | API 장애 | 마지막 스냅샷 사용 + `capturedAt` 그대로 노출. **절대 0으로 채우지 않는다** |
| D3 | 상한가 (거래 미형성) | 거래량 낮음 → MR 저평가. 상한가 플래그 시 MR 최소 80 보정 |
| D4 | 시세 지연 표기 누락 | CI 테스트로 강제: 시세 필드가 있으면 `capturedAt`+`isDelayed`가 반드시 동반 |

## E. AI 실패

| ID | 상황 | 대응 |
|---|---|---|
| E1 | 후보에 없는 `company_id` 반환 | 폐기 + `G1` 기록. 반복되면 프롬프트 회귀 알람 |
| E2 | 존재하지 않는 티커를 설명에 언급 | 설명 텍스트에서 6자리 숫자·기업명 스캔 → 후보 밖이면 설명 폐기(`G2`) |
| E3 | JSON 파싱 실패 | temperature 0 재시도 1회 → 실패 시 FAILED |
| E4 | 전부 ACCEPT (판별력 상실) | 배치 ACCEPT율 > 90% 이면 알람. 프롬프트 회귀 의심 |
| E5 | 금지어 출력 ("수혜주") | 린터 차단(`G3`), 해당 연결 `PENDING`으로 격리 |
| E6 | MEME인데 BR 80 | 30으로 강등 + `G4` |
| E7 | 설명이 경로와 무관 | `used_path_steps`가 비었으면 `G5`, 신뢰도 −30 |

## F. 서비스 운영

| ID | 상황 | 대응 |
|---|---|---|
| F1 | 특정 종목이 매일 1위 (어뷰징 의심) | 동일 종목 7일 연속 상위 노출 시 관리자 알람 |
| F2 | 사용자가 우리 서비스를 시세조종에 이용 | 제보 키워드 로그 보존, 이상 패턴(특정 종목 반복 제보) 차단 |
| F3 | 기업의 삭제 요청 | `connection.status=REJECTED` + 회사별 차단 목록. 대응 창구 명시 |
| F4 | 밈 연결이 명예훼손이 되는 경우 (인물 관련) | `entity.kind=PERSON`이면서 부정적 사건(범죄·사고) 뉴스는 **밈 랭킹에서 자동 제외** |
| F5 | 사망·재난 뉴스에서 밈 생성 | 사건 subtype 블랙리스트(`DISASTER, ACCIDENT, DEATH, CRIME, WAR`) → 밈 랭킹 진입 금지 |

> **F4·F5는 협상 불가 규칙이다.** 재난·사망 뉴스에서 "오늘의 억지 관련주"가 뜨는 순간 서비스는 끝난다. 코드에 하드 차단으로 넣고 테스트로 고정한다.
