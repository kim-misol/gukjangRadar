# STEP 3. Information Architecture

## 1. 라우트 (Next.js App Router)
```
/                          홈 (오늘)
/news/[newsId]             뉴스 상세 + 연결 그래프
/stock/[ticker]            종목 상세 (역방향: 이 종목에 걸린 뉴스)
/entity/[entityId]         개체 허브 ("노루"라는 개체에 걸린 모든 것)   ※ V1.1
/discovery                 오늘의 억지 관련주 / 밈 랭킹 (익명 공개)
/search                    통합 검색 (뉴스·기업·키워드)
/alerts                    키워드 알림 관리 (로그인 필요)
/me                        설정, 저장한 연결
/legal/disclaimer          고지
/api/og/connection/[id]    공유 카드 이미지 (SSR)
```

## 2. 네비게이션
하단 탭 4개 (모바일 우선):
`홈` · `발견` · `검색` · `알림`
→ 종목/뉴스 상세는 탭이 아니라 push 스택. 뒤로가기로 항상 홈에 복귀.

## 3. 콘텐츠 계층
```
Day (오늘)
└── NewsCluster (같은 사건의 기사 묶음)      ← 중복 기사 제거 단위
    └── News (대표 기사)
        └── Entity[]  (태풍, 노루, 기상청…)
            └── Connection[]  (Entity → Company)
                ├── Path (엣지 나열)
                ├── Scores (6종)
                └── MarketSnapshot
```
**NewsCluster가 1급 개념**이다. 국내 언론은 같은 사건을 30개 매체가 쓴다. 클러스터링 없이 피드를 만들면 첫날에 무너진다.

## 4. 홈 화면 블록 순서 (고정)
| 순서 | 블록 | 근거 |
|---|---|---|
| 1 | 😂 오늘의 억지 관련주 TOP3 | 바이럴·재방문 훅 |
| 2 | 🔥 지금 화제인 뉴스 (클러스터 5개) | 본론 |
| 3 | 📈 급등 종목 ↔ 연결된 뉴스 | 세그먼트 B 진입 |
| 4 | 🧭 새로 발견된 연결 (최근 1시간) | 실시간감 |
| 5 | 고지 문구 | 법적 |

## 5. 필터·정렬 축 (전역 공통)
- 정렬: `연결 강도` / `시장 반응` / `최신` — **"기대 수익"류 정렬 없음**
- 필터: connection_type 멀티선택, `사업 연관성 있는 것만`, `밈만`
- 기본값: 정렬=연결 강도, 필터=없음

## 6. 상태별 화면
| 상태 | 처리 |
|---|---|
| 연결 0건 | "설명 가능한 연결을 찾지 못했습니다" + 개체 목록은 노출 |
| 시세 지연/장 마감 | `기준: 2026-08-20 15:30 (지연 시세)` 항상 표기 |
| AI 분석 중 | 뉴스는 먼저 노출, 연결 영역만 스켈레톤 (`analysis_status: PENDING`) |
| 연결 정정됨 | 카드에 `정정됨` 배지 + 사유 |
